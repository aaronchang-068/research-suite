# vault → SP 素材對應規則（scribe skill 內部參照）

> 本文件定義 obsidian vault 與 SP（研究）報告各區段的對應與轉寫規則。動筆前讀一次。

## 1. 素材來源

| vault 元素 | 內容 | 可信度依據 |
|-----------|------|-----------|
| `obsidian/sources/*.md` | 文獻筆記：書目、重點摘錄（頁碼/式號錨點）、與主題關聯 | frontmatter `status` |
| `obsidian/notes/*.md` | 原子筆記：文獻回顧、符號表、數學形式（編號式）、演算法程序、關鍵要點 | frontmatter `status` |
| `obsidian/MOCs/*.md` | 主題脈絡與章節骨架 | — |
| `source/**/*.pdf` | 原始文獻——附錄 E 逐字摘錄與最終查核的唯一依據 | 原文 |

## 2. status → 品質標記對映（與 STD-SP-001 §5.2／§5.5 一致）

| vault status | 意義 | SP 佐證標記 | [C-n] 信度上限 |
|--------------|------|:----:|:----:|
| `stable` | 內容經逐式對照 PDF 原文核驗 | ✓ | ★★（★★★ 需實測＋多來源，vault 文獻研究通常達不到） |
| `reviewed` | 結構驗證通過、內容未逐式核驗 | ⚠ | ★ |
| 筆記內含 ⚠ 標註 | 原刊存疑或無法核驗之處 | ⚠＋沿用筆記的存疑說明 | ⚠ |

## 3. 各區段轉寫規則

### §2.3 文獻回顧
- 素材：範圍內全部 source notes 的「摘要」「與主題關聯」段；原子筆記「文獻回顧」段的演進敘事可整併。
- L1/L2/L3 依 `SP-series-map.md` 系列總覽欄位；判定通則依 STD-SP-001 §5.1——NASA 正式出版品（TM/TP/CR）為 L2、講義類（Okawa、MIT 16.001）為 L3。
- 結構：現況 → 缺口 → 本 SP 定位；行文標記如 `[Grant 1992][L2]✓`。

### Part 3 數學模型
- 直接沿用原子筆記「數學形式」節：公式內容不改寫、原文式號照搬（如 `[Grant 1992, Eq. 8]`）。
- 報告內公式重新統一編號（3-1, 3-2, …），筆記編號↔報告編號的對映記入附錄 B。
- 符號表：合併相關筆記的符號表、消歧義（同符號不同義時改記號並註明）。
- 假設 A-n：從筆記「文獻回顧」中的前提條件萃取，附合理性一句。

### Part 4 推導與驗證
- 每個 §4.x 對應立案表核定的筆記組；敘事以筆記「文獻回顧」為底、依 pxa-standards `references/writing-examples.md` 句型重組為 2–3 段連續敘事。
- 「演算法程序」節轉寫為敘事內嵌的程序描述（不得用粗體步驟標記）。
- 驗證比較：優先使用筆記中已核驗的文獻對比數據（例：低保真 vs 高保真 −10%/+2.3%），標 ✓；`reviewed` 來源的數據標 ⚠。
- 禁止引入 vault 沒有的技術主張——發現素材不足時停下回報，不要補寫。

### Part 5 [C-n]
- 從筆記「關鍵要點」萃取候選結論 → 逐條改寫為規範性語句＋適用條件＋限制＋★。
- 適用條件優先取自筆記「數學形式」的適用條件行與「文獻回顧」的邊界敘述。
- 無法給出適用條件的候選結論：捨棄或降為 Part 4 的局部討論，不得無條件發行。

### 附錄 E 逐字摘錄
流程（每筆引用）：
1. 由報告引用位置找到對應筆記 → 取其頁碼/式號錨點。
2. 開 `source/` 對應 PDF 至該頁（文字型 pdftotext；掃描型 Read 頁面影像）。
3. 擷取支持該引用的**逐字原文**（英文保留原文＋附中譯）。
4. 填入四欄表：引用位置／原文章節／原文摘錄／用途。
- 摘錄取不到（掃描不清等）→ 標 `[原文影像不清，摘錄待補]`，該引用降 ⚠。

### 附錄 A（RTM）
- vault 場景下的追溯鏈：報告陳述 → [C-n]/§4.x → 原子筆記 → source note → PDF 頁碼。
- RTM 表的「來源」欄填筆記名、「驗證位置」欄填報告節碼。

### 附錄 F（術語表）
- 合併範圍內筆記的符號表＋首現術語；繁中／英文原文對照。

## 4. 撰寫時的 vault 迴寫

報告撰寫中若發現筆記錯誤（公式、數據、錨點），依 literature skill 規範修正筆記並重跑 `check_vault.py`——先修 vault 再寫報告，禁止只在報告端修正（違反 SSoT）。
